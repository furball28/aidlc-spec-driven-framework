# 📜 AiDLC AI Behavior Contract & Workspace Constitution
* **Target Enterprise System:** XYZ Start-Up Company Core Infrastructure Stack
* **Enforcer Role:** Lead Business Analyst / AI Workspace Governor
* **Version:** 1.0.0 (Production-Locked)

================================================================================
CRITICAL MANDATE: This document establishes the absolute boundary conditions for all 
autonomous and semi-autonomous AI agents operating within this repository. 
================================================================================

## 🛑 1. The Zero-Assumption Execution Protocol
* **No Interpolation:** The AI agent is strictly forbidden from making guesses, interpreting vague business language, or generating placeholder data structures.
* **Conflict Resolution Loop:** If a requirement gap or cross-repository dependency clash is detected, generation must immediately halt. The agent must present a structured, three-tiered multiple-choice matrix (Options A, B, and C) highlighting the technical pros, cons, and schema impacts of each choice.

## 📊 2. Mathematical Output Volume Allocation
To ensure technical specifications protect the application against real-world failures, all generated markdown and code payloads must follow a strict **60/40 volume distribution**:

* **60% Core Volume Target:** Deep architectural edge cases, error-handling networks, transactional drops, rate limits, schema constraints, validation rules, and race conditions.
* **40% Core Volume Target:** Standard happy-path logic, happy-path business flows, UI component transitions, and successful operational handshakes.

## ⛓️ 3. Multi-Repository & Cross-Tool Context Management
* **Active Node Compliance:** The AI must actively prioritize ingestion tokens delivered via the Model Context Protocol (MCP) server nodes from Jira, Confluence, and Figma.
* **Legacy Code Baseline:** Every code specification must run a background diff against cross-repository legacy code indexes to verify backwards compatibility before suggesting infrastructure upgrades.

## 🔒 4. PII Isolation & Data Containment Rules
* **Edge Anonymization:** Under no circumstances may raw production data, personally identifiable information (PII), API tokens, or secrets pass into the active system context window.
* **Abstract Layers:** All data definitions must pass through an anonymized semantic abstraction layer prior to being written into the workshop logs or architecture specifications.
